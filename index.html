Dex2Web unzips the package, decodes resources.arsc and the binary AndroidManifest.xml, disassembles every DEX method, and transpiles Dalvik bytecode into real JavaScript that executes against a browser-native Android runtime — views, layouts, resources, lifecycle and all.

Drop an .apk here
or click to browse — parsed locally, nothing is uploaded
🔒 Offline by design. Your APK never leaves this tab — no upload, no server, no telemetry. Everything below is computed by JavaScript in your browser.

◆ Real DEX parser

Header, string/type/proto/field/method ID tables, class_data, code_items, encoded values, try tables and the debug_info state machine.

◆ 224 opcodes

Complete Dalvik instruction set decoded across all 20 encoding formats, including packed/sparse switch and fill-array-data payloads.

◆ Faithful codegen

Registers become locals, control flow becomes a basic-block trampoline, and Java try/catch falls straight out of JS exceptions.

◆ Android runtime

~1,500 shimmed java.* / android.* / androidx.* members: Activity lifecycle, resource resolution, layout inflation, widgets, logcat.

◆ Binary XML & ARSC

AXML and the compiled resource table are decoded from scratch, so string, colour, dimension, drawable and layout resources all resolve.

◆ Zero dependencies

No bundler, no CDN, no npm. The ZIP reader uses DecompressionStream with a hand-written DEFLATE fallback.

What runs

        
    
          
  • Pure-Java / Kotlin apps whose UI is built from XML layouts or widget code
    • 
          
  • Activities, fragments, dialogs, toasts, menus, preferences, notifications
    • 
          
  • Resources: strings, plurals, colours, dimensions, PNG/WebP and vector drawables (compiled to SVG)
    • 
          
  • Exception handling, interfaces, enums, generics erasure, inner classes, lambdas
    • 
          
  • Kotlin stdlib, androidx and Material — whatever is bundled in the DEX
    • 
        

      

      

        
What doesn't (yet)

        
    
          
  • Native code — .so libraries would need a WASM/x86 translator; JNI stubs return defaults
    • 
          
  • Jetpack Compose — its composition/slot-table runtime is a second UI toolkit; XML-view apps render, Compose apps boot but paint nothing
    • 
          
  • 64-bit longs are held as JS numbers (exact below 253); bitwise & multiply ops use BigInt
    • 
          
  • Real OpenGL ES, camera, sensors, telephony, multi-window IME
    • 
          
  • Custom onDraw() views get a 2D-canvas draw pass; hardware-accelerated-only effects are approximated
    • 
          
  • Multi-process apps, Binder IPC, content providers backed by a real DB
    • 
          
  • APK signature verification and DRM / integrity attestation
    • 
        

      

      

        
How the transpiler works

        
    
          
  • Registers v0…vN → JS locals; the register file is not modelled as an array, so V8 optimises it
    • 
          
  • Basic blocks → case labels in a for(;;) switch(bb) trampoline, so arbitrary gotos and loops are legal
    • 
          
  • DEX try/handler tables → a catch that resolves the handler block by code address, with real Java stack traces
    • 
          
  • Dalvik's "0 is a null reference" convention is modelled explicitly in every reference operation
    • 
          
  • Method bodies compile on first invocation (a small JIT); AOT export emits one bundle
    •
